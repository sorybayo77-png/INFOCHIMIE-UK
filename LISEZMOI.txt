Version en ligne, synchronisée en temps réel avec Firebase
Développée par M. Alhouseny CISSE et son assistant Sory BAGAYOKO
=====================================================================

Projet Firebase : infochimie-uk
Adresse du site une fois publié : https://infochimie-uk.web.app

CE QUI CHANGE
- Toutes les données (comptes, progression, quiz, dépôts de TP, corrections, notifications,
  évaluations, cours ajoutés) sont enregistrées dans la Realtime Database du projet :
  https://infochimie-uk-default-rtdb.europe-west1.firebasedatabase.app/
- Les changements apparaissent en direct sur tous les appareils : une correction faite par un
  enseignant arrive aussitôt chez l'étudiant, une leçon terminée s'affiche aussitôt dans le
  « Contrôle des étudiants », etc.
- Une pastille en haut de l'écran indique l'état : « En ligne », « Synchronisation… »,
  « Hors ligne » (les modifications partent au retour du réseau) ou « Erreur de synchronisation ».
- Si quelqu'un est en train de saisir un formulaire ou de travailler dans un atelier, la page
  n'est pas rechargée : un bouton « Nouvelles données · Actualiser » apparaît en bas à droite.
- Chaque étudiant ne télécharge que ses propres données (plus rapide, et moins de lectures).
- Les fichiers déposés (images, PDF) sont rangés à part et chargés seulement à l'ouverture.
- Ouverte depuis le disque (double-clic sur index.html) ou dans l'aperçu claude.ai, la plateforme
  reste en « Mode local » : les données restent alors dans le navigateur, comme avant.

    * La zone « Rechercher ou écrire un composé » accepte un nom français ou anglais (sulfate de
      cuivre, chlorure de sodium, caféine, cholestérol, testosterone…), une formule brute
      (C6H12O6), un SMILES (y compris les ions : [Na+].[Cl-], CC(=O)[O-]), un numéro CID PubChem
      (2244) ou un numéro CAS (50-78-2).
    * Les 131 composés intégrés fonctionnent sans Internet. Pour tout autre composé, la plateforme
      interroge automatiquement PubChem (base publique du NCBI, plus de 100 millions de composés) :
      les noms français sont traduits en anglais, la structure 2D est chargée dans l'éditeur et,
      dans l'atelier 3D, le conformère 3D calculé par PubChem est affiché (à défaut, la géométrie
      est construite et optimisée par la plateforme). Bouton « En ligne » pour interroger PubChem
      directement ; suggestions de noms pendant la saisie.
    * Tableau périodique complet (118 éléments) dans les deux ateliers (bouton à quatre carrés).
    * Charges : outils ⊕ et ⊖ (ou touches + et − sur l'atome survolé) ; les ions sont gérés
      partout (hydrogènes implicites de NH4+, H3O+…, formules, SMILES, fichiers .mol/.sdf, 3D).
    * Les métaux ne reçoivent pas d'hydrogènes implicites ; les formules et masses molaires
      couvrent tous les éléments.
  La recherche en ligne nécessite une connexion Internet ; sans réseau, un message l'indique et les
  composés intégrés restent disponibles.
- Comptes :
    * étudiants : matricule (exemple 20200104962) + mot de passe composé (exemple Guinée224@ :
      au moins 8 caractères, une majuscule, une minuscule, un chiffre, un caractère spécial) ;
    * administrateurs : code identifiant personnel, voir ci-dessous.
- Mots de passe enregistrés sous forme d'empreinte PBKDF2-SHA256 salée (100 000 itérations ;
  200 000 pour le compte principal). Les anciennes empreintes sont converties à la connexion.

ADMINISTRATEURS
- Un seul administrateur principal : code identifiant BAGLAM-001. Son mot de passe est celui qui a
  été communiqué au développeur ; il ne figure nulle part dans le code ni dans ce document (seule
  son empreinte PBKDF2 est intégrée). Le compte principal est créé automatiquement, y compris dans
  une base en ligne déjà existante. Il ne peut être ni supprimé, ni désactivé, ni rétrogradé.
- Seul l'administrateur principal crée les autres comptes administrateurs : Utilisateurs › rôle
  « Administrateur ». Le code identifiant est généré automatiquement à chaque création
  (BAGLAM-002, BAGLAM-003, …) et un mot de passe provisoire s'affiche une seule fois ; le nouvel
  administrateur le change dans « Profil ».
- Réservé à l'administrateur principal : créer, modifier, désactiver ou supprimer un administrateur,
  attribuer ou retirer le rôle administrateur, Autorisations, Restaurer une sauvegarde, Mettre en
  service, Réinitialiser la plateforme.
- Tous les administrateurs disposent de la fenêtre « Contrôle des étudiants » (évolution de tous
  les étudiants sans exception et note pour chaque évolution), gèrent étudiants et enseignants,
  et modifient l'accueil (photos, hommage, catalogue).
- Les anciens comptes de démonstration ADM-001 et ADM-002 n'existent plus. S'ils sont encore dans
  une base existante avec le mot de passe public de démonstration, ils sont désactivés
  automatiquement ; l'administrateur principal peut les supprimer dans « Utilisateurs ».
- Le nom affiché du compte principal (« Administrateur principal ») se change dans « Profil ».

MISE EN LIGNE (une seule fois)
1. Ouvrez https://console.firebase.google.com et choisissez le projet infochimie-uk.
2. La base est déjà créée : Realtime Database (europe-west1). Rien à créer.
3. Activez la connexion anonyme : Créer › Authentication › Commencer › onglet « Sign-in method »
   › « Anonyme » › Activer › Enregistrer.
4. Sur votre ordinateur, installez Node.js (https://nodejs.org), puis dans une invite de commandes :
       npm install -g firebase-tools
       firebase login
5. Placez-vous dans ce dossier (celui qui contient firebase.json) et lancez :
       firebase deploy
   Cette commande publie le site ET les règles de sécurité de la base (database.rules.json).
   (Sans l'outil en ligne de commande, vous pouvez aussi copier le contenu de database.rules.json
   dans la console : Realtime Database › Règles › Publier.)
   Ces règles remplacent les règles « mode test » (ouvertes à tous jusqu'au 23/12/2026) : seuls
   les visiteurs de l'application peuvent lire et écrire, et les index (.indexOn) permettent
   à chaque étudiant de ne télécharger que ses propres données.
6. Ouvrez https://infochimie-uk.web.app. Au premier lancement, la base est créée
   automatiquement avec les données de démonstration.

SÉCURITÉ — À LIRE
- Les règles actuelles réservent la base aux visiteurs de l'application, mais toute personne qui
  ouvre le site peut, avec des outils de développeur, lire et modifier les données. C'est suffisant
  pour des essais et la démonstration, pas pour des notes officielles.
- Étape suivante recommandée avant l'usage réel avec des étudiants : passer les comptes sur Firebase
  Authentication (un compte Firebase par utilisateur) et des règles par rôle (un étudiant ne lit que
  ses données, seuls enseignants et administrateurs voient les résultats de tous).

LIMITES DE L'OFFRE GRATUITE FIREBASE (Spark) — Realtime Database
- 100 connexions simultanées au maximum (un onglet ouvert = une connexion). Au-delà, les nouveaux
  visiteurs ne peuvent pas se connecter : pour une grande promotion connectée en même temps,
  passez au forfait Blaze (paiement à l'usage).
- 1 Go de données stockées et environ 10 Go téléchargés par mois.
- Un étudiant ne télécharge que ses propres données ; un enseignant ou un administrateur
  télécharge l'ensemble des étudiants.
- Les fichiers déposés restent limités à 700 Ko (TP) et 1 Mo (documents) pour ménager l'espace.
- Hors ligne : la page continue de fonctionner et envoie les modifications au retour du réseau,
  à condition de ne pas fermer l'onglet entre-temps.
- Suivi de la consommation : console Firebase › Realtime Database › Utilisation.
